# TUM Modulplaner UI Rework: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the planner's surface with five responsive screens (Übersicht, Module, Plan, Woche, Prüfungen) plus one module detail panel and a menu, without changing any calculated result.

**Architecture:** The existing code inside `planner/TUM_Modulplaner.html` (called "the engine") stays untouched. A new facade `PL` (`planner/src/api.js`) reads from and writes through engine functions. New screens (`planner/src/ui/*.js`, `planner/src/css/*.css`) talk only to `PL`. `scripts/build.py` injects the new files as blocks before `</body>`. The old UI keeps rendering into a hidden container and is the test oracle.

**Tech Stack:** Plain JavaScript (ES2020, no modules, no framework), plain CSS, Python 3.12 for build and tests, Playwright (Chromium) for tests.

**Spec:** `docs/superpowers/specs/2026-11-13-ui-rework-design.md`. Read it completely before Task 1. It defines every screen, label, token and the feature map. Background on the engine: `docs/PROJECT_GUIDE.md` sections 4 and 10.

## Global Constraints

- Never edit the engine: nothing between `<script>` (the one starting with `const DATA=`) and the end of the last engine `<script>` in `planner/TUM_Modulplaner.html`, and never the `DATA` literal, the `<script type="text/plain" id="tumuScript">` block, or the markers `/*tumterm:1*/`, `/*tumupd:1*/`, `/*tumlim:1*/`. The only way new code enters the HTML is `python scripts/build.py`.
- Never hand-edit `planner/TUM_Modulplaner.html`. Never print or read the whole file (7 MB); use scripts and `grep -o`/Python slices.
- The nightly workflow commits a new `planner/TUM_Modulplaner.html` around 03:17 UTC. Before every commit: `git pull --rebase origin main`, then `python scripts/build.py`, then tests, then commit. Never overwrite newer module data with an older built file.
- The repo is public. Commit nothing personal: no plan export, no token, no names. `plan/` is git-ignored. Tests must pass without `plan/Modulplan.txt`.
- All UI text is German and copied exactly from the spec. No em dashes anywhere (text, comments, commit messages).
- All new CSS classes and element ids start with `ui-`. New markup uses no `<header>` and no `<main>` element. New CSS selectors are all under `#ui` or `.ui-sheet-root`.
- Screens call only `PL.*`. A screen file must not reference an engine global or `localStorage`. (`api.js` and `ui/boot.js` are the two exceptions.)
- No external requests, fonts, CDNs or libraries. The planner must work from `file://` and from `https://ducalemming.github.io/tum-modulplaner/`.
- Stored plan format is frozen: the `tum_*` localStorage keys keep their names and value shapes. New device-only settings use keys starting with `tum-ui` (hyphen), which the sync ignores.
- Phone layout must have no horizontal scroll at 390 px width. Touch targets at least 44 x 44 px below 1200 px width.
- After each task: all tests pass, the page shows no `pageerror`, one commit per task with message `UI rework: <task title>` plus the attribution lines your harness requires.
- Version: when Task 12 is done, the planner is v87. Add one changelog line to `docs/PROJECT_GUIDE.md` section 5 and update `README.md` (files table, section on development).

## Review Focus

1. A device whose plan is empty (fresh browser): every screen must render an empty state with a hint to open Module, not crash on missing keys.
2. A module in the plan that no longer exists in `DATA.modules` after a data update (`M[c]` undefined): `PL` read models must skip it, as the engine does with unknown codes.
3. Semesters without published times (events carry `vj`): the tag `Vorjahr` appears; no crash when `lvFor(...).list` is empty.
4. Sync applying a remote plan reloads the page: the router must restore the same screen from the URL hash after reload, and the hash form `#/connect/<repo>/<token>` must still reach `sync.js` (boot must not rewrite the hash before `sync.js` has read it).
5. Long names and many items: module names up to 120 characters, 40 issues in Offene Punkte, 15 modules in one semester column; nothing overflows its card at 390 px.

Each of these has a test in the task that owns the code (marked "Review focus N").

## Engine reference (verified 13.11.2026 against v86)

State variables (top-level `let`, reachable from any later script): `marked {code: bracketId}`, `sem {code: 1..4}`, `opt {code: 1}`, `frei {code: 1}`, `pst {code: 'u'|'z'}`, `cand {code: [sem]}`, `done {code: 1}`, `nogo {code: reason}`, `blocks [..]`, `travel {pairs, other}`, `grpSel`, `att {code: {eventKey: status}}`, `hideW {key: 1}`, `collOff Set`, `eoList [{codes, cnt, auto}]`, `optsL {code: [{s, v}]}`, `startSem 'W'|'S'`, `startYear`, `WORK_GOAL`. Constants: `M` (modules), `BR` (brackets), `ORDER` (bracket ids in display order), `MMG` (the four Mastermodule brackets), `ETH_REQ`.

| Need | Engine call | Returns |
|---|---|---|
| ECTS per bracket | `ectsBy()` | `{S: {bracket: sure}, H: {bracket: sure + seat open}, uns, any}` |
| Counting category of a module | `semCat(c)` | `'s'` counts, `'u'` seat open, `'o'` optional, `'ou'` optional and seat open, `'x'` loses a decision |
| Stats of a list of codes | `semStats(codes)` | `{E: {s,u,o,ou,x: ects}, C: {s,u,o,ou,x: [codes]}, es: effort sure, ea: effort all}` |
| Completed ECTS | `doneEcts()` | number |
| Ethics ECTS | `ethEcts()` | number |
| Conflicts | `computeConflicts()` | `{1: [w], 2: [w], 3: [w], 4: [w]}`, `w = {k, txt, A?, B?, c?, e?, cs?}`; kinds `T`, `RF`, `DEP`, `LV`, `PF`, `PFK`, `LF`, `WG`, `PR`, `PT`, `PB`, `EO` |
| Severity | `clashSev(w)` | `'hard'` or `'soft'` |
| Hidden-warning key | `wKey(s, w)` | string used in `hideW` |
| Limited modules in plan | `limPlan()` | `[{c, i}]`, `i = limInfo(c)` |
| Limit texts | `limShort(i)`, `limReg(i)` | strings |

| Events of a module | `lvFor(c, term).list` (all), `allEvents(c)` (timed, chosen groups, planned semester) | event objects, see PROJECT_GUIDE 4.2 |
| Event key | `ekeyG(e)` | string |
| Attendance | `evStatus(c, e)` and `stDefault(c, e)` | `'vor'`, `'onl'`, `'rec'`, `'skip'`, `'done'` |
| Week items | `semItems(s)` | `[{c, e, t, wd, a, b, one, ign, loc, oc, blk}]` and own blocks `{bl, bi, wd, a, b, ...}` (`a`, `b` minutes since midnight, `wd` 1 = Mo) |
| Travel problems | `travelIssues(items)` | list |
| Work hours | `workHours(s)` | object with totals per day |
| Exams | `exItems(s)` | list of `{c, x, n, est}` plus entries without date |
| Groups | `grpList(c)` `{gk: [names]}`, `grpChosenSet(c, gk)` | |
| Either-or | `eoOf(c)`, `eoDropped(c)`, `eoLink(a, b)`, `eoUnlink(c)`, `eoMove(c, ±1)` | |
| Semester options | `optsOf(c)` `[{s, v}]`, `optsApply(c, list)` | |
| Text export | `exportPlan()` | triggers a download of `Modulplan.txt` (capture the Blob, see Task 2) |
| Text import | `parsePlanText(text)` then `applyImport(R, 'replace' | 'merge')` | |

Mutators that already save and re-render: `mark(code, bracket?)`, `unmark(code)`, `setSem(code, s | 0)`, `setStatus(code, [eventKeys], status)` (attendance), `setNogo(c, on, note)`, `toggleMand(c, keys)`, `toggleMandDate(c, key, iso)`, `toggleAusf(c, key, iso)`, `ovrSet(c, key, o)`, `exoSet(c, k, o)`, `optsApply`, `eoLink`, `eoUnlink`, `eoMove`. Plain saves: `save()` (marked), `saveSem()`, `saveOpt()`, `saveFrei()`, `savePst()`, `saveGroups()`, `saveBlocks()`, `saveTravel()`, `saveWorkGoal()`, `saveStart()`, `saveStartYear()`, `saveHideW()`, `saveColl()`, `saveEo()`. Re-render everything the engine shows: `afterChange(code)`.

**Rule for every `PL` action:** find the old UI handler that does the same thing (search the built file for the button label or the function named in the task), and call the same engine functions in the same order. Where the old handler calls `confirm()`, do not call that handler: reproduce its body without the `confirm()` and let the screen ask with `uiConfirm`. If a value exists only inside a render function (`renderPlan`, `renderSem`, `renderWeek`, `renderExam`), copy that computation into `api.js` unchanged and cover it with an oracle test against the old DOM.

Field rules:
- `totals`: `E = semStats(Object.keys(marked).filter(c => M[c])).E`; `sure = E.s`, `seatOpen = E.u`, `optional = E.o + E.ou`, `lost = E.x`, `done = doneEcts()`.
- `brackets.rows`: for each id in `ORDER`: `sure = ectsBy().S[id]`, `withSeats = ectsBy().H[id]`; `state` as in the function `meter` inside `renderPlan`: `'bad'` if limit is `max` or `fixed` and `sure > req`; `'ok'` if (`min` and `sure >= req`) or (`fixed` and `sure === req`), and for `ueber` additionally `ethEcts() >= ETH_REQ`; else `''`. `master.sure` = sum of `S` over `MMG`.
- `rules`: copy the block of `renderPlan` from `let bad=[],open=[];` to the line that pushes `Gesamt: noch … ECTS bis 120.` with `t = ectsBy().S` and `total` = sum of `t`.
- `issues`, in this order and with these types (labels in spec 5.1): `Regel` (one per string of `rules().bad` then `.open`; `title` = text before the first `:`, `detail` = rest); `Entscheidung` (one per group in `eoList`; `title` = codes joined with ` oder `, `action: 'compare'`, `ref` = group index); `Anmeldung` (each `limPlan()` entry with `!limGot(c)`; `title` = code + name, `detail` = `limShort(i) + ' · ' + limReg(i)`, `action: 'seat'`); then per semester from `computeConflicts()`: kinds `LV`, `PF`, `PFK`, `LF`, `PR`, `PT`, `PB` as `Überschneidung`, `WG` as `Weg`, `RF` and `T` as `Reihenfolge`, `DEP` as `Angebot`, `EO` skipped; then `Datenupdate` (one per entry of `recNotes`, `action: 'ack'`). For conflict issues: `full = w.txt`, `soft = clashSev(w) === 'soft'`, `hidden = !!hideW[wKey(s, w)]`, `id = wKey(s, w)`, `codes` from `w.A.c`, `w.B.c`, `w.c`, `w.cs`; `title` = `A.c + ' ' + A.t + ' ↔ ' + B.c + ' ' + B.t` when `w.A` and `w.B` both have `c`, else the part of `w.txt` before the first `:` plus the first module name; `detail` = `w.txt` cut to 90 characters. Non-conflict issues use `id = '0|' + type + '|' + title` and the same `hideW` store.
- `module(c).state.result` (the grey result line, exact texts): cat `s`: `Zählt mit N ECTS.`; `u`: `Zählt mit N ECTS, sobald du den Platz hast.`; `o`: `Zählt nicht (optional).`; `ou`: `Zählt nicht (optional, Platz offen).`; `x`: `Zählt nicht: CODE hat Vorrang (Entscheidung offen).` with the group's first code; done: `Abgeschlossen, zählt mit N ECTS.`; not in plan: `Nicht im Plan.`
- `module(c).term` = `sem[c] ? termOf(sem[c]) : wantTerm(c)`; `events` from `lvFor(c, term).list`; `vj` true if any event has `vj`.
- `week`: build from `semItems(s)`; `counts` = not `ign`; `fill` = `BR[marked[c]].color`; `clash`/`soft` from the conflicts of that semester whose `A` or `B` is the item; `tag` = `'optional'` for cat `o`/`ou`, `'Alternative'` for `x`. `days[].summary`, `figures` and travel items: port from `renderWeek` (the day header `.wkdh`, the badges `.wkects`, `.wkwork`, `.wkfree`, and the travel strips). `mode` `'pre'`/`'post'` = the block weeks (`wkWeekSet`, `wkWeekFilter`, `wkBlockInfo`).
